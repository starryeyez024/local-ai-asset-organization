Set up your own Explorer

This demo uses fictional skill and script catalogs. It does not scan your computer. Search, filter, and open the cards to try it.

To browse your own assets, open this repository in your AI assistant and ask:

Use the agent-setup skill to set up my AI Asset Explorer.

The assistant checks your configuration, helps organize your skill links, and creates a working app and catalog in ~/.local/share/ai-assets-explorer/. The recommended directory for skill links is ~/.agents/skills/; setup checks your existing layout before making changes.

If your assistant cannot find the skill, ask it to read skills/agent-setup/SKILL.md in the checkout.

Your local Explorer includes scan details, refresh times, and an audit of your configured skills directory. Personal catalogs stay on your machine.

About

The Explorer scans your configured skills directory (usually ~/.agents/skills/), the local folder where skill directories and symlinks are collected. It reads your private script catalog when you generate or refresh it, and local launchd and cron definitions for direct script references. It does not watch folders or update automatically. Ask your assistant to refresh your AI Asset Explorer after changes.

Directory scanned:

The scan includes skill folders in that directory and follows symlinks to their targets. For a linked skill, Source identifies the repository the link points into. It does not independently search ~/.claude/skills/, ~/.codex/skills/, project folders, or marketplace caches. Setup’s asset audit can discover skills outside this catalog.

Browse Assets lets you filter Skills and Scripts and narrow scripts to those with a matched job definition. Audit Skills shows local skill entries, broken links, duplicate names, and file age. Browsing does not install, edit, or run anything.

Keep marketplace installations where their installers expect them; do not link managed caches into the skills directory just to include them here.

Where the data comes from

generate-skills-json.py reads the same setup configuration as the linker and scans the folder set by directories.symlinks_dir. Without a configuration file, it scans ~/.agents/skills. It accepts symlinks and real directories. Set SKILLS_ROOT to scan another directory. It reads skill frontmatter and selected Markdown sections, then uses fixed keyword rules to assign tags. The source SKILL.md files remain authoritative.

Browse catalog: skills.json contains skill names, descriptions, tags, and source labels. It is generated locally and excluded from Git.

Local audit: skills-local.json also contains absolute paths and inventory details. It is ignored by Git and must stay on the machine that generated it. Without this file, the page hides Audit Skills.

Registered scripts: scripts-local.json contains private catalog entries, absolute script paths, and any direct launchd or cron job matches. It stays on your machine. Job matches show definitions, not loaded or successful job status.

How tags work

Tool, task, phase, and stage tags are keyword guesses based on each skill's name, description, and the start of its body. A skill can match several tool, task, or stage tags. Phase uses a priority order and defaults to “In Progress.” Role is inferred from a known AI-first module path; other sources use “Other.”

Skill type comes only from metadata.skill-type in the skill's frontmatter: atomic for a small, focused skill intended for reuse by other skills, or workflow for a skill that coordinates a broader sequence of work. Missing or unsupported values appear as “Unclassified.” Names, descriptions, and references to other skills do not determine the type.

If a tag is misleading, update the keyword rules in generate-skills-json.py and regenerate the files. There is no tag editor in the page. A file older than 60 days is marked “Stale” in the local audit as an age cue, not proof that the skill is obsolete.

Update skills and refresh your catalog

  • Update a skill: ask your assistant to edit its source files or get updates from its repository. For marketplace skills, use the marketplace’s installer or update command. The Explorer does not update skill files.
  • Rescan your skills: ask “Use agent-setup to refresh my skill catalog.” The assistant regenerates the catalog from your configured skills directory. Reload the Explorer to see the changes and the new refresh time.
  • Include another skill: ask your assistant to audit your assets and use skill-linker where appropriate, then refresh the catalog. Rescanning alone does not discover skills outside the configured directory.

Keep the original local-ai-asset-organization repository checkout available: it contains the generator needed for refreshes. Your assistant also needs access to the agent-setup skill. If it cannot find the skill, open the checkout in your assistant and ask it to read skills/agent-setup/SKILL.md. The installed app can display its saved catalog without the checkout.

To reopen the app, ask “Use agent-setup to open my AI Asset Explorer.” The assistant uses your saved setup details to open the existing server or start it again.

Guided setup keeps generated files in ~/.local/share/ai-assets-explorer/, outside the source repository. All personal catalog files stay local. The documentation site’s demo uses fictional sample catalogs.

Commands for preparing your local Explorer

Run these in the source checkout, where the generator and Makefile live.

cd /path/to/local-ai-asset-organization/skills-explorer
make run
# open http://localhost:8980

make run prepares the app and data in your personal Explorer folder and starts its local server on port 8980. Stop it with Ctrl+C in the running terminal or by closing that terminal. Run make regen alone to update the data or make serve to preview an existing snapshot. The Explorer uses port 8980 only.

make regen CONFIG=/path/to/agent-config.toml

After a source asset or job definition changes, ask your assistant to refresh the catalog. Source assets remain in their repositories; all generated JSON files stay in your local Explorer folder. The file manager action requires the local server. Catalog refreshes happen when requested, without a scheduled background rebuild.

Requires Python 3.11+ and Make for these commands. Guided setup needs Python 3.11+ without Make. The generator uses only Python's standard library.
