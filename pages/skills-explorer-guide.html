Guide 4 · Skill catalog

Browse your skills without losing the source of truth

AI Assets Explorer is a catalog for discovering skills in a configured local directory. It is a viewing tool, not an agent runtime, installer, or replacement for the actual SKILL.md files.

What it is

A catalog over configured skill folders

The explorer reads the generated skills.json catalog and presents skill names, descriptions, capability groupings, and source repositories in a searchable page. The canonical content remains in each skill’s source folder, especially its SKILL.md and any supporting files.

Browse

Search by name, description, source grouping, or trigger text to find a relevant skill.

Filter by source

Use the Source repository filter to narrow the catalog to labels such as ixd-firefly or tailwind.

Stay read-only

The catalog does not install, invoke, modify, or execute a skill. Agent runtimes still use their own discovery rules.

Mental model

Source folders first; catalog second

Treat each resolved SKILL.md as the source and skills-explorer/skills.json as generated catalog data. If they disagree, update the source skill or generator and regenerate the catalog. The local skills-local.json audit file contains absolute paths, is ignored by Git, and should never be published.

Setup

Set it up locally

  1. Open the repository: clone this project or open the working copy that contains skills-explorer/.
  2. Regenerate the catalog: from that directory, run make regen. The equivalent direct command is python3 generate-skills-json.py.
  3. Preview the static page: run make serve for the local preview server, or use the repository’s normal static-site preview workflow.
  4. Use the actual explorer: open http://localhost:8790 in your browser. On the published site, open the shareable catalog. The primary site navigation intentionally points to this guide instead.
Source directory: the generator defaults to ~/.agents/skills, the local tool-facing skills hub. Set SKILLS_ROOT when generating from another source directory.

Update workflow

Change the skill, then refresh the index

  1. Edit or add the real skill folder in its source repository, including its SKILL.md and supporting files.
  2. Run cd skills-explorer && make regen.
  3. Review the generated skills.json and open the explorer to confirm the name, description, and grouping.
  4. Commit the source skill in its repository and the shareable skills.json in this repository. Keep skills-local.json on the local machine.

GitLab Pages publishes the shareable catalog. The local Audit Skills view and source-file action require the ignored local inventory and preview server. Publishing the catalog does not make local filesystem skills available to a cloud agent.

Boundaries

What the explorer does not do

Not a discovery adapter

It does not make Cursor, Claude Code, Codex CLI, or ChatGPT Work Local discover a skill. Use the compatibility matrix for tool-facing paths and runtime constraints.

Not an installer

It does not create symlinks, copy folders, register plugins, configure MCP, or change a user’s machine. Those actions belong in an explicit setup workflow.

Not a second source

Descriptions should be derived from the source skill metadata. Keep durable procedures and implementation details in the tracked skill folder.

Not an execution sandbox

Viewing a skill card does not run its scripts. The local source-file button only asks the preview server to reveal an inventoried file in the file manager. Review and execute skill code only through the agent/tool workflow that you have deliberately configured.
