Guide 4 · Local catalog

Browse your skills without losing the source of truth

The Skills Explorer is a small, static catalog for discovering what is available in a skills repository. It is a viewing tool, not an agent runtime, installer, or replacement for the actual SKILL.md files.

What it is

A catalog over tracked skill folders

The explorer reads the generated skills.json catalog and presents skill names, descriptions, and capability groupings in a searchable page. The canonical content remains in each skill’s version-controlled folder, especially its SKILL.md and any supporting files.

Browse

Search by name, description, or capability so people can find a relevant skill quickly.

Explain

Give teammates a friendly overview before they open the full procedure or inspect its implementation.

Stay read-only

The catalog does not install, invoke, modify, or execute a skill. Agent runtimes still use their own discovery rules.

Mental model

Source folders first; catalog second

Treat skills/ as the source and skills-explorer/skills.json as generated index data. If they disagree, update the source skill and regenerate the catalog; do not hand-edit the generated file as the primary fix.

Setup

Set it up locally

  1. Open the repository: clone this project or open the working copy that contains skills-explorer/.
  2. Regenerate the catalog: from that directory, run make generate. The equivalent direct command is python3 generate-skills-json.py.
  3. Preview the static page: run make run for the local preview server, or use the repository’s normal static-site preview workflow.
  4. Use the actual explorer: open the separate local Skills Explorer tool. The primary site navigation intentionally points to this guide instead.
Source directory: the generator defaults to ~/.agents/skills, the local tool-facing skills hub. Set SKILLS_ROOT when generating from another source directory.

Update workflow

Change the skill, then refresh the index

  1. Edit or add the real skill folder under skills/, including its SKILL.md, scripts, references, and assets.
  2. Run cd skills-explorer && make generate.
  3. Review the generated skills.json and open the explorer to confirm the name, description, and grouping.
  4. Commit the source skill and the regenerated catalog together so the published view stays reproducible.

GitLab Pages copies the static explorer directory into the published site. A hosted copy is useful for browsing, but it does not make local filesystem skills available to a cloud agent.

Boundaries

What the explorer does not do

Not a discovery adapter

It does not make Cursor, Claude Code, Codex CLI, or ChatGPT Work Local discover a skill. Use the compatibility matrix for tool-facing paths and runtime constraints.

Not an installer

It does not create symlinks, copy folders, register plugins, configure MCP, or change a user’s machine. Those actions belong in an explicit setup workflow.

Not a second source

Descriptions should be derived from the source skill metadata. Keep durable procedures and implementation details in the tracked skill folder.

Not an execution sandbox

Viewing a skill card does not run its scripts. Review and execute skill code only through the agent/tool workflow that you have deliberately configured.
