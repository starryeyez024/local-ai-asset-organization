Guide 4 · Skill catalog

Find a skill and trace it to its source

AI Assets Explorer lets you browse skills from a configured local directory. It displays a catalog of the SKILL.md files. Use your agent or other tools separately to install or run a skill.

What it is

Search your catalog

The explorer reads skills.json to show searchable names, descriptions, capability groupings, and source repositories. Each skill’s SKILL.md and supporting files stay in its source folder.

Browse

Search by name, description, source grouping, or trigger text to find a relevant skill.

Filter by source

Use the Source repository filter to narrow the catalog to labels such as ixd-firefly or tailwind.

Browse without changing files

Browsing leaves skills unchanged and does not install or run them. Each agent still has its own rules for finding skills.

Source files

Keep changes in the source skill

The generator reads each resolved SKILL.md and writes catalog data to skills-explorer/skills.json. If the catalog differs from the source, correct the source skill or generator and regenerate it. The local skills-local.json audit file contains absolute paths, is ignored by Git, and should never be published.

Guided setup

Ask your assistant to open your Explorer

The agent-setup workflow prepares the Explorer after organizing your assets. Your assistant builds the catalog from your configured skills folder, opens it locally, and helps you find a skill to use.

Already set up? Ask “Open my Skills Explorer” or “Refresh my skill catalog.” Your assistant uses the setup notes to find your catalog and start it again.

Your catalog stays on your computer, separate from this repository’s published example. If you have no skills yet, the assistant helps you choose where to start. You can also browse the example catalog to see how it works.

Keep it current

Refresh after changing your skills

Ask your assistant to update a skill at its source and refresh the catalog. It checks that the name, description, and source are correct in the Explorer. Marketplace packages stay under their installer’s control.

Browse Skills helps you find an entry. Audit Skills shows issues in the configured folder, such as broken links. Ask the assistant to investigate an issue or help you use a skill; opening a card does not run it.

Boundaries

What needs a separate tool

Catalog coverage: the generator scans one configured skill directory. Check marketplace registries, other tools’ folders, and runtime enablement separately. A marketplace skill missing from the catalog may be installed elsewhere. Leave managed files in place instead of linking their caches just to include them here.

Agent discovery

Configure skill discovery in Cursor, Claude Code, Codex CLI, or ChatGPT Work Local. The Explorer cannot do that for you. Check the compatibility matrix for tool-facing paths and runtime constraints.

Installation

Ask your setup assistant to make a selected skill available in the tool you use. It handles the installation or linking; the Explorer provides the catalog.

Skill maintenance

Keep descriptions in the source skill’s metadata, and procedures and implementation details in its tracked folder.

Running a skill

Opening a card does not run its scripts. The local source-file button asks the preview server to show an inventoried file in your file manager. Use your configured agent or tool to review and run the skill.
