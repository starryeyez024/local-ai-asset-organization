Guide 2 · Asset organization

Know which copy to maintain

Marketplace plugins, cloned repositories, and custom scripts can leave your AI assets scattered across folders. Use this approach to organize them and keep track of updates. You choose what stays active and review any cleanup before it happens.

The problem

AI assets spread across tools

Copies drift, links break, and updates can erase local changes. Knowing who maintains an asset and how it gets updated helps you choose which copy each tool should use.

Ask an assistant to check one asset or audit the whole setup. It can inspect the folders and discovery rules for you.

The idea

Link skills from repositories you maintain

The original skill stays in its project. A local skills folder can point to the skills you want your tools to use.

Marketplace packages

Let the installer manage its files

Keep marketplace caches and generated installs where their package manager expects them. Record the package, source, version, scope, and update method alongside your repository sources.

A plugin can also come from a local repository. Its format tells you how it is packaged; check the installation record to find out who manages it. Before cleanup, look for the same skill in loose folders and preserve links that other tools still need. To customize a package, maintain your own fork and select it in the target tool.

Lola copies modules and generates assistant files; Claude Code manages plugins by installation scope. Neither requires moving installed files into this repository layout.

Use the skills

Ask for the job you need done

Open this repository in an assistant that can access your local files. Ask it to read the skill linked below and follow its instructions for your project. The skill guides the assistant through the work, including checks in the tools you want to use.

Find and organize what you have

Ask for an AI asset audit. The auditor finds your skills and MCP servers, flags duplicates and broken links, and proposes a cleanup plan for you to review before it changes files.

Read the auditor skill

Make selected skills available locally

Ask the skill linker to make selected project skills available to the agents you name. It checks existing installations, previews the links, and verifies discovery in those tools. Your source files stay in their repository.

Read the linker skill

Customize a shared skill safely

Ask for the override safeguard before changing a team or vendor skill. It tells the assistant to check ownership, edit a personal copy, and update the intended local link. The assistant must follow those instructions; the skill cannot lock files.

Read the safeguard skill

Your part

Choose what to keep and what to change

Tell the assistant which project and tools matter to you. If it finds two skills with the same name or proposes moving files, choose the version you want and review the plan before approving changes. Then check the result in the tool that should use the asset.

A good first request: “Use the AI asset auditor to show me where my skills and MCP servers live, flag duplicates or broken links, and propose a cleanup plan for me to review.”
