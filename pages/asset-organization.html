Guide 2 · Asset organization

Get a clear source for every AI asset

You may have installed marketplace plugins, cloned git repos with skills, and created custom scripts and skills... which means your assets are scattered. This is a suggested approach of how to easily tidy and manage your assets going forward. You decide what should be active and review any proposed cleanup.

The problem

AI assets spread across tools

Copies drift, links break, and updates can erase local changes. A clear owner and update path tells you which version to maintain and how each tool receives it.

You do not need to map every folder or learn every tool's discovery rules before asking for help. Ask for a focused check of one asset, or a broader audit when consolidating your setup.

The idea

Link skills from repositories you maintain

The original skill stays in its project. A local skills folder can point to the skills you want your tools to use.

Marketplace packages

Let the installer manage its files

Keep marketplace caches and generated installs where their package manager expects them. Record the package, source, version, scope, and update method alongside your repository sources.

A plugin can also come from a local repository: “plugin” describes packaging, while the installer record tells you who manages it. Check for overlapping loose skills before cleanup, and preserve shared links needed by other tools. For customization, maintain a deliberate fork and select it through the target tool’s controls.

Lola copies modules and generates assistant files; Claude Code manages plugins by installation scope. Neither requires moving installed files into this repository layout.

Lola bridge: this repository’s relocation script is an unsupported experiment. Testing showed it can move unrelated skills. It is excluded from the recommended setup.

Use the skills

Ask for the job you need done

Use these with an assistant that can access your files and has the skills available. The skills carry the detailed steps.

Find and organize what you have

Ask for an AI asset audit. The auditor finds your skills and MCP servers, flags duplicates and broken links, and proposes a cleanup plan for you to review before it changes files.

Read the auditor skill

Make selected skills available locally

Ask the skill linker to make selected project skills available in your local skills folder. It reports name conflicts and leaves the original skills in place.

Read the linker skill

Customize a shared skill safely

Ask for the override safeguard before changing a team or vendor skill. It guides the assistant to check who owns it, make your changes in a personal copy, and update the intended local link. This is guidance for the assistant, not an automatic file lock.

Read the safeguard skill

Working linker configuration: the bundled linker defaults to ~/.config/ai-tools/ai-tools.toml, using directories.install_dir and directories.symlinks_dir. The private setup repository is a proposed migration. The linker creates selected links; it does not change tool discovery settings, disable old installations, or configure marketplace plugins.

Your part

Review the choices that need your judgment

Tell the assistant which project and tools matter to you. If it finds two skills with the same name or proposes moving files, choose the version you want and review the plan before approving changes. Then check the result in the tool that should use the asset.

A good first request: “Use the AI asset auditor to show me where my skills and MCP servers live, flag duplicates or broken links, and propose a cleanup plan for me to review.”
