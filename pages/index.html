The problem

The same asset ends up in several places

When you use several AI tools or install assets through Lola, NPX, Git, or plugin marketplaces, your skills and MCP servers can end up in different folders. Each tool may find a different set of files.

  • The same skill may appear in a tracked repository, an installed copy, and a symlink elsewhere. It can be hard to tell which version to edit or update.
  • Local changes to an installed skill can disappear when its vendor or package manager updates it.
  • A local path or symlink does not automatically travel with a project or become available to a hosted agent.

How the skills organize them

Keep track of the source

The assistant keeps maintained skills and code in tracked repositories, leaves installed packages with their package managers, and keeps personal setup files private.

Check what each tool supports

The assistant checks which method the tool supports: a symlink, committed file, generated copy, native configuration, or platform-managed package.

Record copies you need to keep

Some tools need their own copy. The assistant records why each copy exists and which source it comes from.


The recommended layout groups repositories you maintain under one folder. Marketplace caches and generated installs stay where their installers expect them. Your private setup repo lives separately under ~/.config/agent-tools/. The linker uses symlinks where the tool supports them; other tools may need a different way to read the same content.

Five principles

Principles behind the setup

The skills use these principles when preparing and checking your setup.

  1. Keep instructions, configuration, and context in separate files.
  2. Record who maintains each asset and how to update it.
  3. Use the delivery method your tool supports: a symlink, committed file, generated copy, native config, or platform package.
  4. Customize a vendor or team asset by copying it, editing your copy, and pointing the intended tool to it. Keep the original intact.
  5. Before automating, check how the tool finds assets, resolves conflicts, and handles installs in each runtime.
