The problem

AI assets multiply faster than 🐰🐰🐰

Each tool has its own discovery locations, configuration format, installer behavior, and runtime boundaries. Copies drift, symlinks break, and a setup that works locally may disappear in a cloud session.

One canonical source

Keep portable procedures, context, and code in a version-controlled physical root.

Verified delivery

Use a symlink, committed file, generated copy, native configuration, or platform-managed package according to the consuming tool.

Documented exceptions

Allow intentional duplication when a tool or runtime cannot consume the canonical representation safely.

Five principles

A simple operating model

  1. Separate concerns: instructions, configuration, and context are different things.
  2. Keep one canonical source: portable content should have a clear owner and update path.
  3. Choose the right delivery mechanism: symlink, committed file, generated copy, native config, or platform package.
  4. Override safely: copy → edit → re-point instead of modifying vendor or team assets in place.
  5. Verify before automating: discovery, precedence, installers, and hosted runtimes differ.

Getting started

Audit first, then change with confirmation

  1. Inventory current skills, instructions, MCP configurations, and runtime targets.
  2. Identify canonical sources and any existing copies or symlink views.
  3. Check the compatibility matrix for the target tool and scope.
  4. Use the ai-asset-auditor for a read-first migration plan.
  5. Make filesystem changes only after reviewing and confirming the plan.
